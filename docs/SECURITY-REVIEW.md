## 已确认的问题：日志操作跟随符号链接

受影响版本：v0.1.0、v0.1.1。修复版本：v0.1.2。

`logs/` 目录由 Xray 服务用户写入，旧版 `xray log del` 却以 root 执行文件截断。如果服务用户被攻陷，攻击者可以将日志路径替换为指向 root 文件的符号链接；管理员随后清空日志时，会以 root 权限清空该目标文件。

这是有前置条件的本地文件破坏风险：需要控制服务账号，并触发管理员的日志清理操作。它不是本次已经证明的远程提权或外传通道。

在隔离 Docker 中，用 root 所有、0600 权限的无害占位文件复现：执行旧版日志清理后，内容由 27 字节变为 0 字节。

修复内容：

- 查看和清空日志均以专用服务用户运行。
- 路径以独立参数传递，避免拼接为 Shell 代码执行。
- 不依赖“先检查链接再打开文件”的方式，以免引入检查与使用之间的竞态。
- 回归测试同时覆盖正常日志清理、指向 root 文件的符号链接、日志查看时不读取该 root 文件，以及保护文件内容保持不变。

Ubuntu 24.04 容器通过 23 项 Bats、PTY 交互和完整核心／Nginx／TLS 集成测试。另在真实 systemd 容器中验证了旧版到候选 v0.1.2 的更新：核心 PID 和节点源文件不变，更新后的已安装命令拒绝清空符号链接指向的 root 文件。

## 正常外联与持久化行为

本项目源码中的出站连接用途可追踪到：

- GitHub：显式安装／更新管理脚本、Xray 核心和规则数据。
- 系统配置的软件源：通过发行版包管理器安装依赖及证书组件。
- 选择的 REALITY SNI：探测 TLS 能力，以及 Xray 的协议目标连接。
- 配置的 DNS：解析目标域名；这是已声明的基础设施流量。
- 用户明确指定的代理出口和伪装网站。
- Certbot 与 Cloudflare 插件：用户要求的 ACME 签发及 DNS-01 TXT 验证。脚本只向插件传递 root 保护的凭据文件路径，没有额外的 Token 上传命令。

本项目安装的持久化资源为 Xray 服务、启动恢复服务、证书部署服务及重试 timer，以及按需添加的 Nginx include／服务依赖和 Certbot 部署钩子。未发现额外 SSH、sudoers、动态加载器或隐藏 cron 入口。

在断开外部网络的隔离容器中，验证了节点添加／修改／删除、出口数据导入、本机二维码生成和脱敏诊断；这些操作不依赖在线二维码站或额外控制服务器。本次没有完成全流程网络系统调用跟踪，不能由此排除所有未覆盖路径的网络行为。

Base64 用于分享链接编码和密钥处理，没有发现解码后作为 Shell 代码执行的逻辑。测试用探测跳过与中断注入需要显式测试环境开关，并限制在 `/tmp/` 状态目录，不是远程控制入口。

## 233boy 代码中的风险与可疑外观

这些发现不等于已确认后门：

- 下载封装使用 `wget --no-check-certificate`，且下载／更新流程没有固定的内容摘要验证。这增加下载被替换时执行恶意代码的风险。
- Xray 的默认 systemd 服务用户为 root；默认管理 API 在本机回环 TCP 端口。后者不是公网开放端口，但权限边界弱于限制文件权限的 Unix socket。
- 脚本有推广链接、分段拼接的推广域名，以及主菜单里的作者彩蛋。所检查路径只打印文本，没有发现这些路径下载或执行推广站代码。
- 二维码备用链接将完整分享链接放入网页 fragment。fragment 本身不会随初始 HTTP 请求发送给服务器，但该页面的 JavaScript 可以读取全部内容。这是需要信任网页代码的额外边界。
- 已获取的二维码页面内联逻辑在浏览器中生成二维码，未见主动上传逻辑。其依赖与声明的 jQuery 2.2.4／jquery-qrcode 0.14.0 组合文件逐字节相同，差异仅为 CDN 参考文件末尾新增的 sourceMappingURL 注释，没有发现额外业务代码。这些旧前端依赖的全部安全属性不属于本次结论。本项目二维码只在本机生成。
